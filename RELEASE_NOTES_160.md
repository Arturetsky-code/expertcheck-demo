# ExpertCheck 16.0 — Quality Leap

## Цель релиза

16.0 — не очередной точечный hotfix. Релиз меняет критерий готовности: количество найденных фрагментов больше не считается качеством проверки. Качество измеряется долей строго завершённых L5-проверок, точностью категоричных выводов, завершённостью AI-очереди и отсутствием критических регрессий.

## Что изменено

### 1. Строгий смысловой контракт доказательства

- Добавлен программный semantic-slot gate для детерминированных положительных выводов.
- Фрагмент должен покрывать ключевые смысловые признаки требования, а не только общий термин.
- Ложное соответствие между одноимёнными, но функционально разными инженерными элементами блокируется до L5.
- Кандидат, не прошедший gate, остаётся вопросом специалисту и не превращается автоматически в нарушение проекта.

### 2. Ужесточённый Judge/Critic

- Judge обязан явно подтвердить `same_entity=true`, `same_property=true` и требуемую модальность.
- Пропущенное подтверждение объекта или показателя теперь блокирует категоричный вывод.
- Critic проверяет только адресные `evidence_id`, принятые Judge; независимость провайдеров остаётся обязательной для L5.
- Повреждённые JSON-ответы распознаются в типовых оболочках, массивах и одиночных решениях.
- После отказа всех независимых AI-линий выполняется одна ограниченная попытка исправления JSON.
- Если соединение работает, но preflight JSON-контракта не проходит, включается безопасное восстановление по одному пакету без права на L5 вместо отключения всей очереди.

### 3. Двухэтапная проверка без потери состояния

- Этап 1 сохраняет детерминированный результат и цифровой снимок проекта.
- При наличии AI-очереди интерфейс автоматически открывает обязательный этап 2 из 2.
- Очередь возобновляется из checkpoint и не требует повторной загрузки PDF.
- После завершения очереди пользователь автоматически переходит к подтверждению состава проекта.

### 4. Честные метрики и отчёты

- «Покрытие найденными кандидатами L3–L5» отделено от строгого L5-покрытия.
- В резюме добавлены подготовленные, обработанные и оставшиеся AI-пакеты и процент завершения.
- Источником подтверждения задания показывается проектный документ, а не само задание на проектирование.
- Рабочие группы вопросов разделяются по предметной теме и ограничены 12 однородными вопросами.

### 5. Золотой стандарт качества

Файл `knowledge/quality_gold_standard_v1.json` фиксирует обезличенные синтетические аналоги критических классов ошибок: пропуск десятичного разделителя, подмену владельца показателя, межраздельное числовое расхождение, ложное смысловое совпадение и точные проверки длительности/производительности. Проектные названия и значения в репозиторий не включаются.

Релизный порог:

- критических регрессий: 0;
- целевая точность категоричных выводов: не ниже 95%;
- целевая завершённость подготовленной AI-очереди: не ниже 95% при доступных провайдерах;
- любое незавершение явно отражается в отчёте и не маскируется под итоговую проверку.
