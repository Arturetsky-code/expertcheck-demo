# ExpertCheck 9.5 Alpha 1.2 — Binding Integrity & Risk Hotfix

## Исправлена критическая ошибка соседних строк таблиц
В плоском текстовом слое PDF общая строка иногда захватывала значение предыдущего объекта.
Пример из тестового комплекта:
- 4.12 Модуль обеспыливания — площадь застройки 23,5 м²;
- 4.13 Здание проборазделки — площадь застройки 89,9 м².

Generic-извлекатель мог ошибочно сформировать «Здание проборазделки = 23,5 м²».
Добавлен Table Row Integrity Guard:
- строит на странице карту надёжных строк `объект → показатель → значение`;
- сравнивает с ней менее надёжные sliding-window находки;
- конфликтующая находка помечается BLOCKED_SHIFTED_VALUE;
- заблокированная запись не участвует в Project Understanding и межраздельной сверке;
- row-locked значения используют исходное имя объекта строки, а не последующий semantic anchor.

## Финальная межраздельная сверка
Перед final high-trust cross-section pass удаляются старые legacy/core межраздельные проверки,
после чего они перестраиваются только на проверенных object-property bindings.
Это исключает сохранение старого ошибочного сравнения рядом с новым корректным.

## Риски экспертизы / Центр отчетов
`engineering_risk_score` теперь читается безопасно из int, float, "71.0", "52,5", None и некорректных строк.
Страница больше не должна падать на `int("71.0")`.
