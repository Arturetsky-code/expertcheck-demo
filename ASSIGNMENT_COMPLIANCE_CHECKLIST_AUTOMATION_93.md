# ExpertCheck 9.3 Alpha 1 — Assignment Compliance & Checklist Automation

## Design Assignment Compliance 1.0
- Добавлен тип документа «Задание на проектирование».
- Задание определяется по имени/типу документа и содержанию первых страниц.
- Извлекаются требования с формулировками «предусмотреть», «должен», «необходимо», «обеспечить», «выполнить» и др.
- Структурированные требования связываются с объектом и параметром.
- Числовые требования сопоставляются с ПД по object + parameter_code.
- Требования на наличие объекта сопоставляются с реестром объектов.
- Смысловые требования не получают ложного автоматического «Да»: статус «Требуется смысловая проверка».
- Результаты доступны во вкладке проекта «Задание на проектирование».
- Результаты включены в Резюме руководителя, Отчёт ГИПа и Техническое приложение.

## Checklist Routing Engine 2.0
- Нормализуются ПЗУ1/ПЗУ2 → ПЗУ, АР1/АР2 → АР, ТХ1/ТХ2 → ТХ, ИОС1.1/ЭС/ЭОМ → ИОС1 и другие варианты.
- Добавлена кнопка «Проверить весь комплект по чек-листам».
- Для каждого распознанного раздела выполняется подходящий корпоративный чек-лист, если он есть в каталоге.
- Разделы, для которых корпоративный чек-лист отсутствует, показываются отдельным списком и не считаются автоматически проверенными.
- Выборочная ручная проверка сохранена.

## Engineering visual layer
- Добавлена очень слабая координатная сетка рабочего поля.
- В правой части фона добавлены ненавязчивые оси/окружность/диагональ в стиле инженерного чертежа.
- Элементы не перехватывают события мыши и имеют низкую непрозрачность.

## Safety
- Задание на проектирование — самостоятельный источник требований, но не нормативный документ.
- Наличие требования в Задании не заменяет нормативную проверку.
- Автоматический вывод по смысловому требованию без структурированных доказательств запрещён.
