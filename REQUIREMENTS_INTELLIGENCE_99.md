# ExpertCheck 9.9 Alpha 1 — Requirements Intelligence

## Цель
Углубление проверки требований Задания на проектирование и НТД без расширения интерфейса.

## Assignment Structure Parser 3.0
- геометрическое восстановление трех колонок Задания: № строки / вопрос / содержание;
- сохранение `source_row`, `source_row_title`, страницы и атомарного требования;
- прекращение разбора основной таблицы перед приложениями;
- отдельное извлечение состава объектов из Приложения 1;
- типизация требований: VALUE_COMPARISON, SET_COMPARISON, CROSS_DOCUMENT_TRACE, PRESENCE_REQUIREMENT, NORMATIVE_COMPLIANCE, CALCULATION_PRESENCE, DRAWING_REQUIREMENT, PROHIBITION_OR_NOT_REQUIRED, DESIGN_DETERMINED, SEMANTIC_ENGINEERING.

## Assignment Compliance Engine 1.0
- числовое сравнение разрешено только для той же инженерной сущности;
- semantic similarity не подтверждает выполнение;
- отсутствие находки не считается невыполнением;
- состав объектов проверяется как set-to-set comparison по приложению;
- для каждого типа требования задается ожидаемый контракт доказательств.

## Normative Reference Audit 2.0
- ужесточены regex нормативных документов, исключены обрывки вроде `СНиП от` и `СНиП 23-`;
- ссылки агрегируются на уровне проекта: уникальный НТД, количество упоминаний, документы и страницы;
- полный список упоминаний остается только в техническом приложении.

## Normative Requirement Layer 2.0
- нормативная ссылка и нормативное требование разделены;
- пункт привязывается к документу только при явной грамматической связи (`п. 4.3 СП ...`);
- библиографический перечень НТД не создает сотни псевдотребований;
- без текста/верификации конкретного пункта нарушение не формируется.

## Normative Compliance Engine 1.0
- структурированные требования нормативной KB получают собственный статус проверки;
- отдельно показывается покрытие базы и готовность к AI-review;
- AI-review допускается только для переданного верифицированного текста нормы и проектных доказательств;
- отсутствие проектного evidence не равно нарушению.

## Отчеты
- `Актуальность НТД` теперь агрегированный реестр уникальных документов;
- новый лист `Проверка требований НТД`;
- `Контекст ссылок НТД` и `НТД — все упоминания` остаются в техническом приложении;
- отчет по Заданию показывает номер строки, раздел/вопрос, тип проверки, ожидаемое доказательство и основание вывода.
