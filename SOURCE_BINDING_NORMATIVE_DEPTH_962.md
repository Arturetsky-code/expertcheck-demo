# ExpertCheck 9.6 Alpha 2 — Source Binding & Normative Depth

## Цель
Развитие «вглубь»: снижение ложных межраздельных замечаний и превращение нормативной базы из списка ссылок в проверяемую цепочку доказательств.

## 1. Source Binding 2.0
Каждый инженерный факт получает физический locator: документ → страница → таблица → строка → колонка/ячейка/координаты (если доступны) и стабильный `source_fingerprint`.

Дубликаты одной физической строки, найденные несколькими извлекателями, теперь считаются **одним источником**, а не независимыми подтверждениями.

Для межраздельного несоответствия требуется доверенное подтверждение минимум из двух независимых семейств разделов. Ранжирование репрезентативного значения выполняется сначала по evidence trust, затем по confidence извлекателя.

## 2. Normative Depth 1.0
Добавлен контракт качества нормативного требования. ExpertCheck различает:
- верифицированный документ;
- верифицированный конкретный пункт/статью;
- предварительное правило маршрутизации;
- право/запрет на категоричный нормативный вывод.

Если документ известен, но конкретный пункт не верифицирован, правило остаётся полезным для предпроверки, однако приложение не должно писать «нарушено требование п. X» как доказанный факт.

`normative_requirements_v3.json` канонически связывает существующие требования с документами реестра, не выдумывая номера пунктов. Незаполненный пункт теперь является явным verification debt, а не скрытым пробелом.
