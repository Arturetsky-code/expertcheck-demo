# ExpertCheck 17.0 — Verified Core

## Цель релиза

17.0 заменяет попытку широкого недоказанного покрытия на проверяемое вертикальное ядро. Приоритет релиза — отсутствие ложных категоричных выводов и воспроизводимый выбор AI-провайдера, а не количество найденных фрагментов.

## AI-контур

- Groq по умолчанию использует фиксированную модель `openai/gpt-oss-120b`; резервные совместимые модели перечислены явно.
- OpenRouter использует фиксированную модель из `OPENROUTER_MODEL`, по умолчанию `openai/gpt-oss-120b`.
- Маршрутизатор `openrouter/free` запрещён для Judge/Critic, поскольку он не гарантирует фактическую модель.
- Judge и Critic получают строгие JSON Schema с обязательными полями и `additionalProperties=false`.
- Транспортный тайм-аут увеличен до 45 секунд; невалидный ответ ремонтируется ограниченно и не блокирует независимый резервный провайдер.
- Judge и Critic должны фактически обслуживаться разными провайдерами; иначе смысловой вывод остаётся на L4.

## Provider Benchmark

В настройках добавлен квалификационный стенд:

- 30 синтетических обезличенных инженерных пакетов;
- 3 повтора каждого кейса;
- строгие пороги доступности API, JSON Schema, смысловой точности, ложных подтверждений и повторяемости;
- сохранение модели, фактического маршрута и p50/p95 задержки;
- применение победителя как Judge и второго квалифицированного провайдера как независимого Critic.

Квалификационный барьер: API не ниже 98%, JSON Schema 100%, смысловая точность не ниже 95%, ложные подтверждения не выше 1%, повторяемость не ниже 95%.

## Единый финальный gate

Категоричный `VERIFIED_OK` или `PROJECT_FINDING` допускается только при наличии:

- адресного доказательства;
- пройденного adversarial gate;
- специализированного детерминированного механизма либо завершённого независимого смыслового консенсуса;
- выполненного машинного контракта Judge/Critic для атомарного AI-вывода.

Gate выполняется после смыслового продолжения и непосредственно перед агрегацией отчётов. Заблокированный вывод превращается в адресный вопрос специалисту либо ограничение системы. Регрессионный XLSX-тест подтверждает, что ложное сопоставление дорожного уширения с ограждением территории не может повторно появиться как L5 в отчёте ГИПа.

## Verified Core

- Быстрый режим: до 30 заданий и 30 чек-листов.
- Расширенный и максимальный режимы: до 100 заданий и 50 чек-листов.
- Кандидаты диверсифицируются по домену, семейству checker-а и ожидаемому разделу до применения лимита.
- В одной возобновляемой итерации выполняется только небольшая часть очереди; checkpoint сохраняется.

