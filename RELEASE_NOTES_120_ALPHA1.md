# ExpertCheck 12.0 Alpha 1 — Coverage Verification Core

## Назначение релиза

Релиз создаёт масштабируемый контур повышения качества без ослабления доказательных барьеров. Главная единица качества теперь не число запущенных правил, а число требований, для которых полностью выполнен контракт доказательства: объект → параметр/решение → значение или признак → единица/квалификатор → раздел → документ → страница/лист.

## Основные изменения

### 1. Адаптивный компилятор исполняемых контрактов

- Общие проверки наличия, проектного решения, чертежа, расчёта и локального атрибута получают консервативный лексический контракт.
- Контракт требует профильный раздел, корректную модальность, локальность существенных условий и явный маркер принятого проектного решения.
- Сложные качественные вопросы без детерминированного критерия остаются экспериментальными и не закрываются автоматически.
- Категоричный результат проходит critic, regression, semantic и adversarial gates.

### 2. Карта покрытия и объяснимые причины остановки

В отчёты добавлена «Карта покрытия» по типам проверок. Для каждого незавершённого пункта формируется причина и отсутствующий слот доказательства, например:

- нет исполняемого рецепта;
- не найден документ и страница;
- найдена неверная модальность — текст вместо чертежа или расчёта;
- не подтверждён существенный квалификатор;
- не определён владелец показателя;
- несовместимы единицы;
- вывод заблокирован независимым смысловым контролем.

Граница автоматизации отображается в отчёте, но не включается в план мероприятий ГИПа как замечание проекта.

### 3. Междокументные проверки классификаций

Добавлена безопасная сверка адресуемых категориальных значений между независимыми разделами:

- класс опасности ОПО;
- категория надёжности электроснабжения;
- степень огнестойкости;
- категория помещения/здания по пожарной опасности.

Несоответствие формируется только при двух явных значениях из разных документов и разделов. Неоднозначная привязка не создаёт замечание.

### 4. Расширение инженерных показателей

Добавлены и включены в объектную модель, нормализацию и межраздельную сверку:

- расчётная/максимальная электрическая мощность;
- влажность материала;
- насыпная плотность;
- преобразование кг/м³ ↔ т/м³.

Высота насосной станции не используется как специальное правило: известная запись без запятой не должна создавать ложный риск; в комплекте после экспертизы этот показатель исключён.

### 5. Внешний эталон без загрузки в интерфейс

`tools/run_external_benchmark.py` индексирует большой корпус отдельно от приложения, строит SHA-256-манифест и повторно обрабатывает только изменившиеся файлы. Сырые проектные материалы и замечания не входят в дистрибутив.

Примеры:

```bash
python tools/run_external_benchmark.py index --corpus /path/to/corpus --cache /path/to/cache
python tools/run_external_benchmark.py evaluate --benchmark benchmark.json --before-results before.json --after-results after.json --output metrics.json
```

## Пользовательский сценарий проверки

Для тестирования релиза достаточно прежнего комплекта из 12 файлов. Ограничение размера загрузки не влияет на внешний эталонный прогон: он является отдельной процедурой разработчика и не выполняется через интерфейс ExpertCheck.

## Совместимость и безопасность вывода

- `NOT_FOUND` не является несоответствием.
- Неопределённый владелец факта не может быть восстановлен догадкой.
- Неизвестная редакция НТД означает необходимость проверки актуальности, а не вывод «устарел».
- Adversarial downgrade немедленно исключает пункт из автоматического покрытия.
- Отчёт до подтверждения комплектности и состава имеет предварительный статус.
