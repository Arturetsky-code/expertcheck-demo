# ExpertCheck 10.2 Alpha 1 — Verification Factory

## Цель
Кратно ускорить рост качества без обязательного подключения профильной команды для ручной разметки и наполнения базы.

## Verification Recipe Factory
- Автоматически строит кандидаты проверочных рецептов из корпоративных чек-листов, накопленной практики экспертизы и нормативной базы.
- Требования Задания могут компилироваться в рецепты динамически во время проверки проекта.
- Каждый рецепт содержит уровень L1–L5, метод проверки, scope, ожидаемые разделы, требуемые типы evidence, положительную/отрицательную политику и обязательную политику воздержания.

## Critic Gate
- Рецепты проходят автоматическую критику до рабочего применения.
- L4/L5 не допускаются как автоматические только на основании текстового/семантического попадания.
- Нормативное правило не может стать категоричным без требования VERIFIED_CLAUSE.
- Правила из экспертной практики используются для приоритизации и поиска риска, но сами не доказывают нарушение.

## Synthetic Regression Gate
Для каждого рецепта генерируются защитные сценарии: отсутствие evidence, неправильный владелец, слабый semantic hit; для числовых правил также несовместимые единицы и отличающееся значение. Рецепт получает статус TRUSTED только после critic + regression gate.

## Текущая автоматически построенная библиотека
На базе существующих знаний ExpertCheck сформировано 1068 кандидатов, из которых 112 прошли консервативный gate как TRUSTED. Остальные сохранены как EXPERIMENTAL и не имеют права самостоятельно давать положительный вывод.

## AI Recipe Designer / Critic
Добавлен безопасный интерфейс для использования подключённого AI как генератора и критика рецептов. AI возвращает только структурированный кандидат; статус TRUSTED он самостоятельно присвоить не может. При использовании нескольких AI-оценок disagreement всегда приводит к консервативному отказу.

## Learning without dependency on specialists
Ручные решения по чек-листам, если пользователь их всё же принимает, автоматически сохраняются как labeled regression cases. Они полезны для улучшения рецептов, но система не зависит от наличия такой разметки.

## Precision-first
Экспериментальный рецепт не может автоматически выдать «Соответствует». Это сознательно может уменьшить coverage, но защищает от ложноположительных инженерных выводов.
